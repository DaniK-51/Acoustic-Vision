# Acoustic-Vision — идея продукта

**Стадия:** P0–P3 backend реализован (engines, mesh, field, runs, catalog, scene.patch). GUI — прототип в `gui/` (срезы GUI1–4 + V0.1.1); полный редактор помещений (V0.2) — в работе / по запросу. Контракты — [`engines.md`](engines.md); модули и API — [`ARCHITECTURE.md`](../ARCHITECTURE.md).

## 1. Видение (согласовано)

**Acoustic-Vision** — open-source инструмент акустического анализа помещений.

Пользователь строит 3D-сцену помещения, расставляет источники звука, запускает разные алгоритмы акустического расчёта и **видит**, как звук распределяется в пространстве: куда и с какой силой приходит, где отражения, где появляются артефакты (фокус, мёртвые зоны, эхо).

### Ключевые свойства продукта

| Свойство | Смысл |
|----------|--------|
| **Open-source** | Прозрачные алгоритмы, свои engines, research-методы |
| **3D-редактор** | Базовый в v1 (примитивы + import); полный DCC — позже |
| **Два режима** | Interactive: WS-дельты сцены при перетаскивании; Compute: кнопка «Расчёт» (можно часы, GPU) |
| **Мульти-алгоритм** | Одна сцена → разные методы → история запусков |
| **Видимость отражений** | Лучи, ранние отражения, сила и направление |
| **Источники** | Свои + каталог приборов; данные каталога используем «как есть» (качество спеков — вне зоны ответственности) |
| **Без замеров** | Не делаем микрофонный/телефонный measurement pipeline |
| **Open research** | Методы подбираем research-ом; engine расширяет, что именно считать (точка / поле / лучи / …) |

### Что в продукте

1. **3D-сцена** — геометрия помещения, материалы с α(f), мебель/препятствия (mesh).
2. **Источники** — позиция, ориентация, мощность, АЧХ, диаграмма направленности.
   - custom (пользовательский);
   - **built-in catalog** популярных колонок/динамиков/приборов;
   - (опц.) позже — импорт карточек из внешних баз.
3. **Запуск расчёта** — выбор engine, его параметров (для mesh-методов — сетка/дискретизация), кнопка «Расчёт».
4. **Визуализация** — то, что умеет алгоритм: IR, поле, лучи, отражения, «куда с какой силой».
5. **История запусков** — прежние прогоны сцены, вернуться, сравнить глазами.

### Чего в продукте нет

- Замеров помещений (смартфон/микрофон/калибровка) — **не наша тема**.
- Гарантии качества спеков в каталоге источников — используем найденные данные как есть.
- Обязательной «1 секунды» на любой алгоритм — тяжёлые методы могут считаться **часами** (GPU/CPU), это норм.
- Тяжёлого scientific Study/diff-конвейера в v1 — достаточно **истории запусков**.

## 2. Проблема

Акустический расчёт помещений (студии, переговорные, залы, классы) обычно разбит между:

- табличными калькуляторами RT60 — быстро, но без IR, геометрии и поля;
- тяжёлыми CAE-пакетами — точно, но долго, дорого, крутой UX;
- research-кодом — гибко, но не как продукт и не визуально.

Нужен инструмент, где **сцена → алгоритм → картина звука** и можно быстро крутить источники/материалы/методы.

## 3. Ключевые принципы

| Принцип | Смысл |
|---------|--------|
| **Ядро отделено от UI** | C++ вычисления; GUI — Electron+Vue+Three.js; связь REST/WS |
| **Методы расчёта — плагины** | Новый алгоритм не трогает API, GUI и чужие движки |
| **Один контракт результата** | IR + metrics + spatial field (+ paths) |
| **Interactive first** | Быстрая правка сцены (WS-дельты); тяжёлый расчёт — job |
| **Open research** | Можно подтягивать алгоритмы из работ; golden-бенчи |
| **Честные пределы модели** | Геометрическая акустика ≠ волновая; LF-моды — отдельным engine |
| **Без measurement** | Не строим pipeline замеров |

## 4. Сценарии использования

- **Расстановка колонок** — куда поставить, чтобы не было фокуса и мёртвых зон.
- **Материалы** — как ковёр/панели меняют поле и RT60.
- **Сравнение методов** — где ISM и RT расходятся, что видит каждый алгоритм.
- **Разбор артефактов** — эхо, flutter, концентрация отражений в точке.
- **Обучение** — видеть отражения и силу звука в точках приёмника.
- **IR экспорт** — WAV для аурализации в других инструментах.

### Два режима работы

| Режим | Когда | Протокол | Результат |
|-------|-------|----------|-----------|
| **Interactive** | Перетаскивание, правка сцены | WS `scene.patch` (v1-дельты: `move`, `setPower`); статика уже на бэке | Обновлённая Scene Store; опц. draft-preview |
| **Compute** | Кнопка «Расчёт» | REST `POST /simulations` → job; WS `job.progress` | Полный Result (IR / field / rays / …); может занимать **часы**, GPU/CPU |

Интерактив **не** обязан пересчитывать полную акустику за 1 с. Быстрая обратная связь — синхронизация сцены; тяжёлые методы — отдельной кнопкой.

### Scenario — единица работы

JSON-документ (`schemas/scenario.schema.json`):

- **room** — rect (w×h×d + материалы граней) или mesh (uri, unit, materialOverrides);
- **materials** — α(f) по октавным полосам + scattering;
- **sources** — позиция, ориентация, power, АЧХ, directivity (custom или ref каталога);
- **receivers** — точки наблюдения (и/или spatial grid для поля);
- **params** — `engine`, `maxReflectionOrder`, `sampleRate`, `durationSec`, `bandsHz`, `speedOfSound`, `capturePaths`, `airAbsorption`, `signedIr`, `fieldGrid`, `methodParams`.

### Result — единый для всех методов

```json
{
  "metrics": {
    "rt60": { "500": { "schroederT30": 0.42, "sabine": 0.40, "eyring": 0.41 } },
    "edt":  { "500": 0.31 },
    "earlyReflections": [{ "t": 0.012, "amp": 0.4, "order": 1 }]
  },
  "ir": { "sampleRate": 48000, "durationSec": 1.5, "channels": 1, "channelNames": ["src-1:rcv-1"], "bandsHz": [] },
  "field": { "nx": 32, "ny": 16, "nz": 24, "origin": [0, 0, 0], "cellSize": 0.19, "bandHz": 1000, "unit": "energy", "values": [] },
  "rays": { "paths": [{ "points": [[0, 0, 0], [1, 0, 0]], "amplitude": 0.9, "order": 1 }] }
}
```

### Run / история запусков

Один **run** = scenario + engine + params + Result. История — список runs по сцене (без сложного Study/diff в v1). UI может показать два run’а рядом глазами.

Запись run (P2e): `id` = **`runId`** (`run-…`, уникальный ключ истории), `jobId` — handle для артефактов (`/v1/jobs/{jobId}/…`), engine, scenarioName, sceneVersion (может отсутствовать), submittedAt/finishedAt, state, paramsDigest (engine + ключевые sim-параметры). `GET /v1/runs/{id}` принимает **либо `runId`, либо `jobId`**. Все терминальные job'ы (включая failed/cancelled) попадают в историю.

## 6. API (контракт для GUI)

- Base: `http://localhost:8787/v1`
- WS: `ws://localhost:8787/v1/events`
- JSON only. Ошибки: `{ type, title, status, detail, fields? }`.

Реализовано (P0–P3 backend):

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/v1/health` | статус, версия |
| GET | `/v1/engines` | descriptor'ы методов (caps + paramsSchema + artifacts) |
| GET | `/v1/bands` | сетка частот |
| GET | `/v1/source-catalog` | built-in каталог приборов (мощность, АЧХ, directivity) |
| POST/GET | `/v1/scenarios`, `/v1/scenarios/{id}` | сохранить/прочитать сцену → `sceneId`, `sceneVersion` |
| POST | `/v1/simulations` | запуск (inline scenario или `{"sceneId"}`) → job (WS progress) или `?sync=1` |
| GET | `/v1/runs` | **история запусков** (новые сверху; фильтр `?engine=`) |
| GET | `/v1/runs/{id}` | один run + ссылки на result/ir/field (принимает `runId` или `jobId`; ссылки по `jobId`) |
| GET | `/v1/jobs/{id}` · POST `/v1/jobs/{id}/cancel` | async lifecycle |
| GET | `/v1/jobs/{id}/result` \| `/ir.wav` \| `/field` | артефакты (metrics / IR / field / rays по caps engine) |

Запланировано (фаза GUI/редактора — пока не реализовано): CRUD `/v1/materials`, `/v1/rooms`, `/v1/sources`, `/v1/receivers`; `POST /v1/rooms/import`; `GET/PATCH/DELETE /v1/scenarios/{id}`; `GET /v1/scenarios/{id}/validate`. Сегодня room/materials/sources/receivers живут inline в scenario JSON.

WS: `scene.patch` / `scene.patched` / `scene.error` · `job.progress` · `job.succeeded` · `job.failed` · `job.cancelled` · (P3) `simulation.reflection`

**Interactive UX:** WS `scene.patch` / `scene.patched` — дельты позиций при drag; статическая часть сцены живёт на бэке. Compute UX: WS `job.progress` (можно часы).

## 7. GUI (Electron + Vue + Three.js)

- **3D-редактор (базовый v1)**: box/extrude, mesh-import, стены/пол/потолок, материалы. Полный DCC — в конце roadmap.
- **Источники**: gizmo (позиция/ориентация), custom + **каталог** (данные «как есть»).
- **Interactive**: drag → `scene.patch` на бэк; сцена единая на сервере.
- **Compute**: кнопка «Расчёт», выбор engine и его параметров (в т.ч. сетка, если метод требует).
- **Визуализация**: то, что вернул алгоритм (поле, лучи, IR, маркеры).
- **История запусков**: список run’ов, вернуть, сравнить визуально.
- Только REST/WS — GUI не линкует C++.

## 8. Roadmap

| Фаза | Поставка | Статус / критерий готовности |
|------|----------|------------------------------|
| **P0** | Engine API + Sabine/Eyring + ISM + metrics + CLI | **done** — RT60 из IR ≈ аналитике; «новый engine = файл + register» |
| **P1** | av-api REST/WS, jobs, runs history, schemas | **done** — контракт `/v1` заморожен |
| **P2** | OBJ/glTF, mesh, RayTracing, hybrid, paths, **spatial field** | **done** — glTF считается; поле на гриде |
| **P3 backend** | source catalog, Scene Store, `scene.patch` | **done** |
| **P2.5** | Dynamic plugin SDK (C ABI) | **только по запросу** |
| **P3 GUI** | Electron+Vue+Three.js | прототип **есть** (`gui/`: GUI1–4 + V0.1.1); редактор помещений (V0.2) — **в работе / по запросу** |
| **P4** | Research-алгоритмы, сравнение runs | **later** — research engine подключён без правок GUI |
| **P5** | Полноценный 3D-редактор (DCC-фичи) | **later** — сложная геометрия без внешних редакторов |

### Не в v1

Measurement/mic/phone pipeline · FDTD/волновые солверы, дифракция · real-time DSP 60 FPS · HRTF · multi-room · distributed compute · auth/multi-tenant · тяжёлый Study/diff · обязательный GPU в P0 (движки с GPU — позже, job queue уже под long-run).

## 9. Риски

| Риск | Мера |
|------|------|
| Ошибки в ISM (1/r, α vs √α) | Golden-тесты + письменные конвенции |
| Mesh ломает чистый IMS | Capability flags → `400`; RT — отдельный engine |
| Interactive путают с полным пересчётом | Явно разделять scene.patch vs compute job в UX |
| Каталог приборов — юридически/данные | Только факт. параметры, CC-данные; custom всегда работает |
| Плохие mesh из DCC | Import-валидатор (warnings) |
| GUI «прирастает» к ядру | Запрет: только HTTP/WS |
| Scope creep (measurements, auralization) | Явные non-goals |

## 10. Словарь

| Термин | Определение |
|--------|-------------|
| **IR** | Impulse Response — импульсный отклик |
| **RT60** | Время реверберации (−60 дБ) |
| **EDT** | Early Decay Time (0…−10 дБ) |
| **ISM** | Image Source Method — метод зеркальных источников |
| **Engine** | Реализация метода расчёта за `IEngine` |
| **Run** | Один прогон сцены алгоритмом (история запусков) |
| **Scenario / Scene** | Комната + материалы + источники + приёмники + params |
| **Spatial field** | Поле уровня/энергии на гриде / по объёму |
| **Source catalog** | Каталог реальных приборов (мощность, АЧХ, directivity) |
| **АЧХ** | Амплитудно-частотная характеристика источника |
| **α(f)** | Коэффициент звукопоглощения по частоте |
| **Scattering** | Коэффициент рассеяния (для RT; ISM v1 не использует) |
| **Bands** | Октавные полосы (default 125…4k Hz) |
