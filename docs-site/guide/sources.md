# Источники

Источник в Scenario — это `id`, `position` и набор необязательных полей: мощность, ориентация, диаграмма направленности. Плюс built-in каталог приборов с готовыми карточками.

## Поля источника

```json
{
  "id": "src-1",
  "position": [1.2, 1.5, 1.0],
  "powerDb": 80.0,
  "orientation": { "yawDeg": 30, "pitchDeg": -5 },
  "directivity": { "type": "cardioid" }
}
```

| Поле | Обязательно | Смысл |
|------|-------------|-------|
| `id` | да | уникальный ключ |
| `position` | да | `[x, y, z]`, метры; **y = высота** (Y-up) |
| `powerDb` | нет | уровень в dB SPL @ 1 м на оси |
| `orientation` | нет | наведение: `yawDeg`, `pitchDeg` |
| `directivity` | нет | тип ДН + опциональные полярные кривые |

Приёмник проще: `id` + `position` — точка наблюдения.

## powerDb

`powerDb` — **уровень звукового давления** (dB SPL @ 1 м на оси), не электрические ватты. Такой же смысл в карточках каталога.

Как мощность применяется в расчётах:

| Метод | Эффект `powerDb` |
|-------|------------------|
| `ray-tracing`, `hybrid` | масштаб энергии источника: `10^(powerDb / 10)` |
| `image-source` | v1 строит IR в относительной шкале (амплитуда единичного источника) |
| `sabine-eyring` | не используется — RT60 от мощности не зависит |

То есть абсолютные дБ на `field` и в IR RT-методов отражают `powerDb`, а сравнение «что громче» между методами корректнее делать в относительных дБ.

Изменить мощность интерактивно можно без пересоздания сцены — операция `setPower` в WS `scene.patch` (см. [Симуляция](/guide/simulation)).

## Ориентация (yaw / pitch)

```json
"orientation": { "yawDeg": 30, "pitchDeg": -5 }
```

| Поле | Смысл |
|------|-------|
| `yawDeg` | поворот вокруг `+Y`: 0 — ось в `+Z`, положительный поворот — к `+X` |
| `pitchDeg` | наклон вверх/вниз: положительный — вверх |

Оба поля по умолчанию `0`. Ориентация хранится в сценарии и показывается в GUI (инспектор источника, роза направлений); поворот через `scene.patch` в v1 не передаётся — GUI сохраняет ориентацию новым snapshot-сценарием.

## Диаграмма направленности (directivity)

```json
"directivity": {
  "type": "cardioid",
  "description": "упрощённая кардиоида",
  "horizontal": {
    "freqsHz": [250, 500, 1000, 2000],
    "anglesDeg": [-180, -90, 0, 90, 180],
    "gainDb": [
      [0, -6, -20, -6, 0],
      [0, -6, -20, -6, 0],
      [0, -6, -20, -6, 0],
      [0, -6, -20, -6, 0]
    ]
  }
}
```

| Поле | Смысл |
|------|-------|
| `type` | `omni` / `dipole` / `cardioid` / `custom` |
| `description` | свободный текст |
| `horizontal` | полярная кривая в азимутальной плоскости |
| `vertical` | полярная кривая в вертикальной плоскости |

### Полярная кривая (polarCurve)

| Поле | Форма | Смысл |
|------|-------|-------|
| `freqsHz` | `[f1, …]` | полосы; строка `gainDb[i]` принадлежит `freqsHz[i]` |
| `anglesDeg` | `[a1, …]` | углы дискретизации |
| `gainDb` | `rows × len(anglesDeg)` | усиление в дБ, по строке на частоту |

Кривые — **относительные** усиления: 0 дБ — осевая точка источника, не абсолютный уровень. Если кривые не заданы, потребитель (GUI) может подставить аналитический пресет для `omni` / `dipole` / `cardioid`; `custom` без кривых не имеет ДН.

Сейчас диаграмма — часть модели данных и визуализации (полярный график в GUI). Ядра расчёта сэмплируют направления изотропно: направленность ещё **не** применяется в физике отскоков. Это ограничение v1 — не ждите, что cardioid изменит поле до появления соответствующей поддержки в engines.

## Каталог источников

Built-in каталог — карточки приборов «как есть», с обязательным disclaimer. Данные — примеры паспортных значений, **не** проверенные вендорские измерения.

### Доступ

| Способ | Что |
|--------|-----|
| `GET /v1/source-catalog` | JSON каталога (всегда `200`; пустой список, если файл не найден) |
| GUI | панель «Source catalog», кнопка «Вставить источник» |
| Файл | `data/source_catalog.json` в репозитории |

Файл ищется так:

1. `AV_SOURCE_CATALOG` (путь к JSON) — переопределение;
2. `source_catalog.json` рядом с исполняемым файлом `av-api`;
3. иначе — пустой каталог + предупреждение в stderr.

### Карточка (entry)

| Поле | Смысл |
|------|-------|
| `id`, `name` | идентификатор и название |
| `manufacturer` | опционально; для generic-карточек отсутствует |
| `category` | группировка: `studio-monitor`, `pa`, `omni`… |
| `powerDb` | типовой max SPL @ 1 м на оси |
| `spectrum` | `bandsHz` + `responseDb` — **относительные** смещения АЧХ к `powerDb` |
| `directivity` | та же структура, что у источника |
| `notes`, `disclaimer` | пояснения; disclaimer обязателен |
| `sourceUrl` | опциональная ссылка; лучше опустить, чем выдумать |

`responseDb` спектра — справочные данные карточки; движки пока не раскладывают источник по полосам по этой АЧХ (полосовой расчёт идёт по материалам и broadband-мощности).

### Вставка в сцену

GUI вставляет источник в центр комнаты (со сдвигом, чтобы не накладываться на существующие) и **переносит** `powerDb` и `directivity` карточки — полярный график переживает save/load. Вставка пересохраняет сценарий: `scene.patch` в v1 умеет только `move` и `setPower`.
